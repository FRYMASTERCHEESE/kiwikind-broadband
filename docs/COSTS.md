# Cost control

No domain, trademark, company registration, hosting subscription, payment service or wholesale agreement has been purchased by this build. No new Play developer account is needed. Existing account/ChatGPT costs remain governed by their plans; a private preview is not an unlimited free production hosting promise.

| Item | Development choice | Expense before live service |
|---|---|---|
| Source control | Existing private GitHub account | Actions/storage over included quotas may cost; use manual Android builds and 7-day artifact retention |
| Backend | Local Django + SQLite; one shared deployment | Persistent hosting, backups, HTTPS operations, mail and monitoring need a host; select a current priced offer before ordering |
| Domain | Platform preview URL only | Optional now; annual registration/renewal if chosen, after clearance |
| Android | Existing Play account; native app, no paid SDKs | Device testing/time, signing-key custody and any applicable platform costs |
| Business | No registration purchased | Registration/advice/accounting/insurance and trademark fees if chosen depend on structure |
| Wholesale | No supplier enabled | Real provider may require setup fees, deposits, minimum commitments and recurring connection/network charges; obtain written quotes |
| Payments | Disabled | Transaction/settlement/dispute fees if later enabled |

Local synthetic development can avoid incremental infrastructure spend. A genuine ISP has unavoidable wholesale and operational costs. No reliable live monthly budget can be quoted before supplier and hosting decisions. Do not rely on an ephemeral free database for customer records. Avoid adding a second backend or separate Android database; scale from the single instance only when measured demand requires it.
